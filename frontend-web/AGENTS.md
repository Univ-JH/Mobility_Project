# Frontend-Web 폴더 전용 AI 개발 규칙

중앙 관제 관리자용 웹 대시보드 개발 시 관통해야 하는 컴포넌트 및 로직 규칙입니다.

## 핵심 규칙
1. **재사용성 높은 UI 모듈 분할 (Atom Pattern)**: UI 컴포넌트는 단일의 거대한 파일(한 파일 2~300줄 이상)로 설계하지 말고, `components/` 폴더 내에 공통 버튼, 공통 카드 등 아주 작은 원자(Atom) 단위로 쪼개서 제작하며 선언적 뷰를 지향합니다.
2. **Typescript API 계약 철저 준수**: Fetch 함수를 호출할 때 받아오는 응답값은 항상 백엔드에서 정해둔 (혹은 정의된 `schemas/`) 응답 DTO와 동일하게 매핑 인터페이스로 구현해야 합니다. (`any` 절대 사용 금지)
3. **비동기 엣지케이스(오류, 지연) 처리 방어 체계**: 수많은 장치를 모니터링 하는 만큼, API 지연이나 일시적 오류(5xx 등)가 자주 관측될 수 있습니다. `React Query`를 적극 활용하여 쿼리 실패 시 Retry, Loading Skeleton View, Error Boundary 등을 기본 탑재하여 설계하세요.
4. **관리 환경 다크 패턴 지양**: 높은 명암비와 넓은 데이터 표(Data Table) 접근을 중시합니다. 접근성(a11y) 기준을 충족하는 태그 트리(시맨틱한 HTML 요소 배분)를 사용하세요.
5. **Cursor Rules**: 추가 프론트엔드 일반 권장 룰셋은 `.cursor/rules/20-frontend-react-typescript.mdc`를 참고합니다.
