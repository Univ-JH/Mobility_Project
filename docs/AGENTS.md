# Docs 폴더 전용 AI 개발 규칙

이 공간에서는 기술적인 명세와 시스템 아규먼트 등이 문서화됩니다. AI가 명세를 갱신할 때는 다음 준칙을 따라 이정표를 명확히 세워주세요.

## 핵심 규칙
1. **GitHub Markdown 포맷팅 활용 (GFM)**: 긴 줄글이나 산문형 서술은 금지됩니다. 명세는 직관적이어야 하므로 마크다운 표(Table), 굵은 텍스트 강조, 체크리스트 포맷을 가장 1순위로 사용하여 가독성을 극도로 높이세요.
2. **"항상 맞는 문서(SSOT)" 동기화 원칙 (중요!)**: 정책 및 스키마 구조 변경을 기술 문서에 등록했다면 필수로 본 문서의 상/하단에 기준이 된 **디렉터리 파일의 레퍼런스(예: `backend/schemas/` 기반 동기화 됨)** 및 업데이트 시점(날짜) 뱃지를 반드시 넣어 문서가 죽지 않도록 방어하세요.
3. **객체 필드 정의의 명확화**: JSON API 형태의 페이로드 예시를 보여줄 때는 필수적으로 값의 자료형(String, Integer, Boolean)과 Required(필수 파라미터)/Optional 여부를 부석에 달아 개발자 혼선을 없애주세요.
4. **추상적인 어조 금지**: "아마도 ~일 수 있다", "이 값을 대충 쓰면 됩니다" 등의 어휘는 금지됩니다. 확정적이고 기능주의적인 말투("이 값을 1.0으로 넣어야 제한이 해제됨" 등)를 채용해 백서(Whitepaper) 느낌을 유지하세요.
