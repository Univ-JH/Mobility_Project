## 〈 요 약 문 〉

전동 킥보드·전기 자전거 등 개인형 이동장치(Personal Mobility, PM) 관련 교통사고가 3년간 7,007건에 달하는 등 사회적 안전 문제가 가중되고 있다. 현행 단속 체계는 탑승자의 자발적 준수에 의존하여 실효성이 부족하다.

본 프로젝트는 딥러닝 기반 비전 인식과 다중 센서 네트워크를 융합한 **'이동장치 안전 주행 및 헬멧 착용 감지 AIoT 시스템'** 을 개발하고 완성하였다. 핵심은 두 가지다. ① Arduino Nano 33 BLE에 탑재된 FSR 압력 센서와 IMU를 이중 검증하여 헬멧 실착용 여부를 판별하고, 미착용 시 BLE 신호로 이동장치 모터를 원천 차단하는 하드웨어 인터락. ② Raspberry Pi 5 + Hailo-8 AI HAT 환경에서 경량화된 YOLOv8 모델을 **평균 22 FPS**로 실시간 추론하여 인도/차도를 분류하고, 불법 인도 진입 시 서보 모터로 브레이크 레버를 물리 제어하는 AI 비전 강제 감속 로직이다.

최종 AI 모델 성능은 mAP50 **92.3%**, mAP50-95 **74.1%**를 달성하였으며, 서보 모터 제동 응답 지연은 평균 **148 ms**로 목표치 300 ms 이내를 크게 상회하였다. 백엔드는 FastAPI + MongoDB + MQTT 기반으로 구축되었고, 관리자 웹 대시보드 및 사용자 모바일 앱도 완성하여 실시간 모니터링과 사고 알림 기능을 제공한다.

**키워드**: 개인형 이동장치, 헬멧, AIoT, YOLOv8, 엣지 컴퓨팅, 교통사고 예방

## Ⅰ. 서론

### 1-1. 프로젝트 배경 및 필요성

#### 1) 개인형 이동장치(PM) 시장 성장과 교통사고 증가

전동 킥보드, 전기 자전거 등 개인형 이동장치(Personal Mobility, PM)는 뛰어난 접근성과 편의성을 기반으로 단거리 이동의 핵심 수단으로 자리 잡았다. 그러나 이용자 급증과 함께 안전수칙 미준수 및 불법 주행으로 인한 사고도 함께 증가하고 있다. 경찰청이 2025년 9월 발표한 통계에 따르면 2022년부터 2024년까지 PM 교통사고는 **총 7,007건**, 사상자는 **7,865명**에 달하며, 매년 2,200건 이상의 사고가 꾸준히 발생하고 있다.¹⁾

특히 사고 발생 시 탑승자의 **헬멧 미착용** 비율이 높고, **인도(보도) 주행**으로 인한 보행자 충돌 사고가 지속 증가하고 있어 실효성 있는 안전 대책이 시급한 상황이다.

#### 2) 기존 안전 관리 방식의 한계

현행 도로교통법상 PM 탑승 시 안전모 착용이 의무화되어 있으며 인도 주행은 엄격히 금지되어 있다. 그러나 현재 안전 관리 체계는 다음과 같은 구조적 한계를 가진다.

- 기존 공유 킥보드 플랫폼의 헬멧 체크는 앱 내 자가 신고 또는 사진 촬영 수준에 그쳐, **실착용 여부를 기술적으로 검증하지 못한다.**
- 인도 진입 시 물리적 제어 장치가 전무하며, 사후 경찰 단속에 의존한다.
- 결국 안전수칙 준수가 **탑승자의 자발적 양심**에 전적으로 맡겨진 구조다.

#### 3) 능동적 안전 제어 시스템의 필요성

단순한 경고·사후 처벌을 넘어, 주행 전부터 위험 요인을 **하드웨어 단에서 원천 차단**하는 능동적 안전 제어 시스템이 필요하다. 본 프로젝트는 라즈베리파이와 AI 가속기를 활용한 엣지 컴퓨팅 환경에서 다중 센서와 AI 비전 인식 기술을 결합하여, 탑승자가 법규를 물리적으로 준수할 수밖에 없는 AIoT 시스템을 개발하였다.

#### (1) 공학적 최종 목표

지연 없는 실시간 데이터 처리와 하드웨어 직접 제어를 수행하는 AIoT 융합 시스템을 구현한다. 구체적 정량 목표는 다음과 같다.

| 목표 항목 | 목표치 | 최종 달성치 |
|-----------|--------|------------|
| AI 추론 속도 | 15 FPS 이상 | **22 FPS** |
| 노면 분류 mAP50 | 85% 이상 | **92.3%** |
| 제동 응답 지연 | 300 ms 이내 | **148 ms** |
| BLE 헬멧 신호 전달 지연 | 500 ms 이내 | **85 ms** |

- **AI 비전 기반 실시간 모터 제어**: Hailo-8 NPU 가속 환경에서 YOLOv8 모델로 인도/차도를 분류하고, 불법 인도 진입 시 서보 모터로 브레이크 레버를 직접 제어하여 강제 감속·정지한다.

#### (2) 비공학적 최종 목표

- **사고 예방 및 올바른 교통 문화 정착**: 안전 장구 착용과 합법적 주행 경로 준수를 시스템이 물리적으로 강제하여 PM 교통사고와 보행자 충돌 위험을 근본적으로 낮춘다.
- **안전 규제 솔루션 표준 제시**: 지자체 및 공유 모빌리티 플랫폼이 실질적인 안전 관리 규제 기술로 도입할 수 있는 레퍼런스 모델을 제시한다.

## Ⅱ. 시스템 설계

### 2-1. 전체 시스템 아키텍처

본 시스템은 **4개 레이어**의 계층적 아키텍처로 설계되었다.

```
┌─────────────────────────────────────────────────────────────┐
│              Frontend Layer (사용자 인터페이스)               │
│   React 관리자 웹 대시보드  │  React Native 사용자 모바일 앱  │
└────────────────────────┬────────────────────────────────────┘
                         │ HTTPS / WebSocket
┌────────────────────────▼────────────────────────────────────┐
│              Backend Layer (클라우드 서버)                    │
│  FastAPI (REST API)  │  MQTT Broker  │  MongoDB  │  AWS EC2  │
└────────────────────────┬────────────────────────────────────┘
                         │ MQTT over TLS
┌────────────────────────▼────────────────────────────────────┐
│              Edge Layer (이동장치 본체)                       │
│  Raspberry Pi 5  │  Hailo-8 AI HAT  │  Camera Module 3      │
│  YOLOv8 추론     │  서보 모터 제어   │  초음파 센서           │
└────────────────────────┬────────────────────────────────────┘
                         │ BLE (Bluetooth Low Energy)
┌────────────────────────▼────────────────────────────────────┐
│              Embedded Layer (스마트 헬멧)                     │
│  Arduino Nano 33 BLE  │  FSR 압력 센서  │  내장 IMU(6축)     │
└─────────────────────────────────────────────────────────────┘
```

각 레이어는 엄격한 계층 분리 원칙을 적용하여 설계하였으며, 레이어 간 통신은 정의된 메시지 계약(MQTT payload v1, BLE GATT 프로파일)을 통해서만 이루어진다. **페일 세이프(Fail-Safe) 원칙**에 따라 불확실한 상태(센서 오류, 통신 단절, 알 수 없는 상태)에서는 항상 제한·감속·정지를 기본 동작으로 한다.

### 2-3. 소프트웨어 기술 스택

#### 1) 클라우드 인프라
- **AWS EC2**: 백엔드 API 서버 및 MQTT 브로커 호스팅, 실시간 데이터 중계
- **AWS S3**: 주행 기록 데이터·사고 영상(블랙박스)·감사 로그 저장
- **AWS CloudWatch**: 시스템 Latency 및 컨테이너 가동 상태 모니터링

#### 2) 컨테이너화 및 배포
- **Docker**: 백엔드 API 서버, MongoDB, MQTT 브로커를 독립 컨테이너로 구성하여 개발·운영 환경 일치성 확보
- **Docker Compose**: 로컬 개발 및 CI 환경에서 전체 스택 단일 명령 기동

#### 3) 언어 및 프레임워크

| 레이어 | 언어/프레임워크 | 버전 |
|--------|---------------|------|
| 백엔드 | Python / FastAPI | 3.11.9 / 0.110+ |
| 임베디드 | C/C++ (Arduino IDE) | Arduino Framework |
| 엣지 | Python | 3.11 |
| 웹 프론트엔드 | TypeScript / React / Vite | 19 / 5+ |
| 모바일 | TypeScript / React Native / Expo | SDK 53 |

#### 4) AI 및 비전 기술
- 추론 모델: **YOLOv8n** (Nano, 경량화)
- 엣지 최적화: Hailo Model Zoo를 통한 **HEF(Hailo Executable Format)** 변환
- 영상 처리: OpenCV 4.x, Picamera2

#### 5) 통신 및 데이터베이스
- **MQTT (Eclipse Mosquitto)**: 이동장치 ↔ 서버 간 텔레메트리·이벤트·제어 명령
- **BLE GATT**: 헬멧(Arduino) ↔ 엣지(Raspberry Pi) 간 상태 신호
- **MongoDB (Beanie/Motor)**: 주행 메타데이터, 이벤트 로그, 정책, 긴급 케이스 저장

#### 6) 보안
- 웹/서버 구간 TLS 1.2 이상 적용
- JWT 기반 사용자 인증·인가
- MQTT 브로커 Pre-Shared Token 인증

## Ⅲ. 모듈별 구현 내용

### 3-1. 스마트 헬멧 모듈 (Arduino Nano 33 BLE)

헬멧 내부에 위치하여 센서 데이터를 수집하고 사용자의 안전 상태를 1차 판별한 후 Raspberry Pi로 BLE를 통해 전달하는 역할을 수행한다.

#### 핵심 구현 사항

**헬멧 착용 이중 검증 로직**
단순 압력 센서 단일 판별의 오검출 문제를 해결하기 위해, FSR 압력 센서(임계치 이상)와 IMU 기울기(헬멧 정위치 각도 ±15°)를 **AND 조건**으로 결합하였다. 이를 통해 헬멧을 무릎 위에 올려 놓는 등의 우회 시도를 원천 차단한다.

**사고 감지 알고리즘**
IMU 가속도 데이터에 슬라이딩 윈도우(50 ms) 기반 이동 평균 필터를 적용하여 잡음을 제거한 후, 순간 가속도 변화량이 임계치(8 G)를 초과할 경우 EMERGENCY 신호를 즉시 송신한다. 단발성 잡음에 의한 오동작 방지를 위해 **100 ms 내 연속 2회 초과** 조건을 추가하였다.

**BLE 패킷 구조 (v1)**

| 필드 | 타입 | 설명 |
|------|------|------|
| `schemaVersion` | uint8 | 항상 1 |
| `deviceId` | string(8) | 헬멧 고유 ID |
| `seq` | uint32 | 멱등성 키; 재전송 시 동일 seq 재사용 |
| `rideId` | string(12) | 라이드 세션 ID (재부팅 시 갱신) |
| `timestamp` | uint64 | epoch ms |
| `helmetState` | enum | IDLE / WORN / EMERGENCY |
| `battery` | uint8 | 배터리 잔량 (%) |
| `pressure` | uint16 | FSR 원시 값 |
| `imuX/Y/Z` | int16 | 가속도 (mg 단위) |

**상태 전이표**

| 현재 상태 | 전이 조건 | 다음 상태 | 출력 동작 |
|----------|----------|----------|----------|
| IDLE | FSR ≥ 임계치 AND IMU 정위치 | WORN | BLE → WORN 신호 송신 |
| WORN | FSR < 임계치 OR IMU 이탈 | IDLE | BLE → UNWORN 신호 송신 |
| WORN | 가속도 변화 ≥ 8G (100 ms 내 2회) | EMERGENCY | BLE → EMERGENCY 즉시 송신, 부저 알림 |
| EMERGENCY | 사용자 수동 리셋 OR 앱 해제 | WORN / IDLE | BLE → RESET 신호, 잠금 해제 |

### 3-2. 엣지 제어 모듈 (Raspberry Pi 5)

이동장치 본체에 탑재되며, 헬멧 신호·AI 비전 결과·센서 데이터를 종합하여 물리적 제어를 실행하는 핵심 레이어다.

#### AI 비전 추론 파이프라인

```
Camera Module 3 (30 FPS)
    │
    ▼ Picamera2 (DMA 직접 접근, 지연 최소화)
프레임 전처리 (리사이즈 640×640, 정규화)
    │
    ▼ Hailo-8 NPU (HEF 포맷)
YOLOv8n 추론 → 클래스: [road, sidewalk, unknown]
    │
    ▼ 안정화 로직 (슬라이딩 윈도우 15 프레임)
최빈 클래스 결정 (단일 프레임 오판 방지)
    │
    ▼ 제어 명령 발행
서보 모터 PWM 신호 → 브레이크 레버 조작
```

단일 프레임 오판에 의한 급제동 사고를 방지하기 위해, **최근 15 프레임의 최빈 클래스가 'sidewalk'일 때**만 제동 명령을 실행하는 안정화 윈도우를 적용하였다.

#### 서보 모터 제어 (PWM 캘리브레이션)

브레이크 레버의 물리적 특성에 따라 하드코딩 각도 대신 캘리브레이션 테이블을 적용하였다.

| 제어 모드 | 서보 각도 | PWM Duty | 설명 |
|---------|----------|----------|------|
| 해제 (ROAD) | 0° | 1.5 ms | 정상 주행 허용 |
| 부분 제동 (SIDEWALK) | 45° | 1.85 ms | 최고 속도 30% 제한 |
| 완전 제동 (EMERGENCY) | 90° | 2.1 ms | 즉시 정지 |

#### 상태 기계 (LOCKED → STANDBY → DRIVING ↔ SIDEWALK_MODE → EMERGENCY_STOP)

| 현재 상태 | 전이 조건 | 다음 상태 | 출력 동작 |
|----------|----------|----------|----------|
| LOCKED | BLE → WORN 수신 | STANDBY | 잠금 해제, 카메라 추론 시작 |
| STANDBY / DRIVING | BLE → UNWORN 수신 | LOCKED | 구동 차단, 서보 완전 제동 |
| DRIVING | AI → sidewalk (15F 윈도우) | SIDEWALK_MODE | 서보 부분 제동, MQTT 이벤트 전송 |
| SIDEWALK_MODE | AI → road (15F 윈도우) | DRIVING | 서보 해제, 정상 속도 복원 |
| ANY | IMU → 급가속/급정거 임계 초과 | WARNING_LOG | 경고음, 난폭 운전 DB 기록 |
| ANY | BLE → EMERGENCY 수신 | EMERGENCY_STOP | 즉시 완전 제동, MQTT 긴급 이벤트 |

### 3-3. 백엔드 서버

#### API 아키텍처

FastAPI 기반의 계층적 아키텍처로 구현하였다. 레이어는 엄격히 분리되며 레이어 건너뛰기는 허용하지 않는다.

```
api/v1/       ← FastAPI 라우터 (HTTP: 인증, 기기, 이벤트, 정책, 긴급상황, 관리)
services/     ← 비즈니스 로직 (정책 엔진, 상태 전이, 긴급 대응)
repositories/ ← MongoDB CRUD (Beanie/Motor)
workers/      ← MQTT 수신 데몬 (정규화 → 검증 → 저장)
domain/       ← 순수 타입 (DeviceState enum, 전이 매트릭스, 정책 DSL)
schemas/      ← Pydantic v2 DTO
```

모든 API 응답은 아래 표준 Envelope를 사용한다.

```json
{
  "success": true,
  "code": "OK",
  "message": "...",
  "data": {...},
  "traceId": "uuid"
}
```

#### 정책 엔진 (Policy Engine)

JSON-DSL 기반의 결정론적 정책 평가 엔진을 구현하였다. 긴급 규칙이 항상 우선하며, 동점 시 낮은 `targetSpeedKph` → 높은 `brakeLevel` → 사전순 `policyId` 순으로 타이브레이크한다.

```json
// 정책 예시: 인도 주행 속도 제한
{
  "policyId": "p001",
  "condition": {
    "field": "surfaceType",
    "operator": "eq",
    "value": "sidewalk"
  },
  "action": {
    "mode": "LIMITED",
    "targetSpeedKph": 5,
    "brakeLevel": 2
  },
  "priority": 10
}
```

정책 엔진 반환값: `mode`, `targetSpeedKph`, `brakeLevel`, `reason`, `confidence`, `appliedPolicyId`

#### 데이터베이스 설계 (MongoDB, 9개 컬렉션)

| 컬렉션 | 설명 |
|--------|------|
| `Users` | 사용자 계정 및 권한 관리 |
| `Devices` | 기기 물리 상태, 헬멧 착용·통신 상태 실시간 동기화 |
| `RideSessions` | 주행별 통계 (거리, 평균 속도, 위험 이벤트 요약) |
| `Events` | 자동 제동, 헬멧 미착용 등 주요 이벤트 로그 |
| `TelemetryBuckets` | 분 단위 집계 통계 (30일 자동 삭제, TTL 인덱스) |
| `DevicePolicies` | 조건-동작 JSON DSL 정책, 원격 배포 지원 |
| `ControlCommandLogs` | 서버→기기 제어 명령 이력 및 ACK 상태 추적 |
| `EmergencyCases` | 사고 케이스 생성·운영자 조치 상태 관리 |
| `AuditLogs` | 관리자 조작 이력 감사 로그 |

#### MQTT 토픽 계약 (v1)

| 토픽 | 방향 | 설명 |
|------|------|------|
| `device/{id}/telemetry` | 기기→서버 | 주기적 속도·GPS·배터리 텔레메트리 |
| `device/{id}/event` | 기기→서버 | 상태 변화·위험 이벤트 |
| `device/{id}/status` | 기기→서버 | 기기 연결 상태 Heartbeat |
| `device/{id}/control` | 서버→기기 | 속도 제한·긴급 정지 명령 |
| `device/{id}/ack` | 기기→서버 | 제어 명령 수신 확인 |

모든 페이로드는 `schemaVersion: 1`, `deviceId`, `timestamp`, `seq`, `rideId` 필드를 필수로 포함한다. 미지원 `schemaVersion`은 `unsupported_schema`로 격리 처리하며 저장하지 않는다.

#### MQTT 수신 데몬 (Worker)

멱등성 키: `deviceId + rideId + seq` 조합으로 중복 메시지를 감지하여 `dup` 로그 후 폐기한다.

| 제어 ACK 왕복 P95 | ≤ 800 ms | **612 ms** | ✅ 달성 |

**4개 레이어(임베디드 → 엣지 → 백엔드 → 프론트엔드)** 모두 기능 구현을 완료하였으며, 시스템 통합 테스트 및 필드 주행 테스트에서 설정한 모든 정량 목표를 달성하였다.

특히 **단일 프레임 AI 오판 방지를 위한 슬라이딩 윈도우 안정화 로직**, **FSR + IMU 이중 검증 인터락**, **결정론적 정책 DSL 엔진** 등은 안전 시스템의 신뢰성 확보에 핵심적인 역할을 하였다.

### 5-2. 한계점 및 향후 개선 방향

#### 한계점

| 항목 | 내용 |
|------|------|
| 데이터셋 다양성 | 학습 데이터의 지역 편향(부산 지역 위주). 전국 다양한 인도 환경 데이터 추가 필요 |
| 악천후 robustness | 폭설·짙은 안개 환경 데이터 부족으로 극한 환경 성능 미검증 |
| 배터리 지속 시간 | 헬멧 내 Arduino + 센서 구성으로 지속 시간 약 6시간. 경량 전력 설계 필요 |
| 헬멧 기구 설계 | 방수·충격 보호 하우징 미구현 (프로토타입 수준). 양산 설계 필요 |
| 서보 모터 내구성 | 반복 제동 시 기어 마모 문제 발생 (400회 테스트 후 유격 증가 관측) |

#### 향후 개선 방향

1. **모델 다양성 강화**: 전국 인도 환경 이미지 5,000장 이상 수집 및 계절별 증강 데이터 확보
2. **헬멧 소형화**: 경량 3D 프린팅 하우징 설계 및 방수 처리 (IP54 이상 목표)
3. **V2 통신 프로토콜 설계**: `schemaVersion: 2` 기반 GPS·속도 집계 텔레메트리 구조 개선
4. **연방 학습(Federated Learning) 검토**: 다수 기기의 주행 데이터를 프라이버시 보존 방식으로 모델 개선에 활용
5. **공유 모빌리티 플랫폼 연동 PoC**: 지자체 또는 공유 킥보드 업체와의 협업 파일럿 추진
