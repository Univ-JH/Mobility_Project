# Infra 폴더 전용 AI 개발 규칙

이 공간에서는 IaC(Infrastructure as Code) 혹은 배포, Dockerfile, bash script 와 관련된 작업이 이루어집니다. 시스템의 골격을 만지는 만큼 철저한 보안 원칙을 수반해야 합니다.

## 핵심 규칙
1. **보안 정보 제로(Zero-Trust) 커밋 (가장 중요)**: 클라우드 AWS Secret Access Key, DB 패스워드, 장치 인증키 등은 이 공간, `docker-compose.yml`, 쉘 스크립트 어디에도 하드코딩 되어선 안 됩니다. 인증값은 환경 변수화(`${MONGO_DB_PWD}`)하고 샘플 구조인 `.env.example` 형식으로만 껍데기를 만들어 업로드합니다.
2. **경량화 이미지 지향 (Alpine/Slim)**: Dockerfile 기반 이미지 구성 시, 빌드 타임을 줄이고 클라우드 비용을 절감하기 위해 불필요한 기본 패키지는 지양하고 `-alpine` 혹은 최적화된 최소 단위 베이스 이미지를 선점하세요. 멀티스테이지 빌드를 권장합니다.
3. **루트 컨테이너 배제 원칙**: 컨테이너 유저 권한이 특별한 연산 및 바인딩이 있지 않은 이상 `root`로 작동하는 것을 피하세요. 별도의 유저 소유 공간(예: `USER appuser`)으로 보안을 올립니다.
4. **재사용/안정성 확보 (Tagging)**: 언제 서버를 지웠다가 올려도 똑같은 호환과 버전으로 빌드되도록 `image: ubuntu:latest` 혹은 `node:latest` 처럼 `latest` 지시자 사용을 지양하고 구체적인 버전을 확실히 명시하세요.
